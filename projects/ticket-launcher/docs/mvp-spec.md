# Ticket Launcher MVP 仕様

## 目的

利用者がチケット発売直前に販売ページへ迷わず移動できるようにする。購入操作そのものの自動化、ログイン代行、CAPTCHA 回避、サイト操作の自動化は MVP の対象外とする。

## 対象ユーザーフロー

1. 利用者がイベント名、発売日時、販売 URL を入力して保存する。
2. アプリが通知権限を確認し、発売 1 分前のローカル通知を予約する。
3. 一覧からイベントを開くと、発売までの残り時間を秒単位で表示する。
4. アプリが前面にある状態で発売時刻になったら、販売 URL を一度だけ開く。
5. バックグラウンドまたはロック中は通知を表示し、利用者が通知をタップすると販売 URL を開く。

## 機能要件

### 登録

必須項目:

- イベント名
- 発売日時
- `https` の販売 URL

過去日時、不正 URL、空のイベント名は保存しない。登録済みイベントは編集・削除できる。

### 通知

- 発売日時の 60 秒前にローカル通知を 1 件予約する。
- 60 秒未満前に登録した場合は、保存直後に明確な案内を出し、発売時刻用の通知またはアプリ前面でのカウントダウンへ誘導する。詳細動作は実装前にテスト可能な規則として確定する。
- 編集時は古い通知を取り消して再予約する。
- 削除時は関連通知を取り消す。
- 権限拒否時も登録は保存できるが、通知されないことを画面上に表示する。

### カウントダウン

- 端末時計を基準に、発売日時との差分を表示する。
- 画面表示中は秒単位で更新する。
- 0 秒をまたいだとき、同じイベントの URL を複数回開かない。
- アプリが再び前面に戻ったとき、現在時刻から再計算する。

### URL 起動

- `https` URL のみを受け付ける。
- 前面表示中は 0 秒到達時に販売 URL を開く。
- 通知にはイベント識別子と URL を関連付け、タップ時に対象 URL を開く。
- iOS の制約により、バックグラウンドやロック中の自動起動は保証しない。

### 保存

MVP のデータは端末内に保存する。モデルは最低限、安定した ID、イベント名、発売日時、URL、作成日時、更新日時を持つ。初期実装では SwiftData を候補とし、Xcode プロジェクト作成時に対象 OS と合わせて確定する。

## 非機能要件

- オフラインで登録済みイベントとカウントダウンを利用できる。
- 秘密情報やチケットサイトの認証情報を保存しない。
- Dynamic Type と VoiceOver の基本操作を妨げない。
- 主要な時刻ロジックを UI から分離して単体テスト可能にする。
- 多重タップや再表示で URL を重複起動しない。

## MVP 対象外

- X や共有シートからの自動取り込み
- Web ページからの日時抽出
- 券種の自動選択
- Safari 拡張
- ログイン、購入、決済の自動化
- CAPTCHA や待機室の回避
- サーバー同期、複数端末同期

## 受け入れ条件

- 有効なイベントを登録・編集・削除できる。
- 1 分前通知が実機で届く。
- カウントダウンが 60 秒、1 秒、0 秒の境界で正しく表示される。
- 前面状態で 0 秒になったとき URL が一度だけ開く。
- ロック状態では自動起動せず、通知タップで正しい URL が開く。
- 通知拒否、不正 URL、過去日時で利用者が次の操作を判断できる。
- アプリ再起動後も登録内容が復元される。
- 関連単体テストが通り、実機確認結果が開発ログに記録される。
