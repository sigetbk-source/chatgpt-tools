# Ticket Launcher MVP 仕様

## 目的

利用者がチケット発売を確実に思い出し、発売直前に販売ページへ迷わず移動できるようにする。購入操作そのものの自動化、ログイン代行、CAPTCHA 回避、サイト操作の自動化は MVP の対象外とする。

## 対象ユーザーフロー

1. 利用者がイベント名、5分刻みの発売日時、販売 URL、任意のメモを入力して保存する。
2. アプリが通知権限を確認し、発売 10分前、5分前、3分前、1分前のローカル通知を予約する。
3. 利用者が通知をタップすると、アプリが対象イベントの発売待機画面を開く。
4. 利用者が待機画面を前面に表示したiPhoneをロックせずに待つと、アプリが発売時刻にSafariで販売 URL を開く。
5. 通知を見逃した場合も、イベントは発売済みとして一覧に残り、販売ページを手動で開ける。

## 機能要件

### 登録

必須項目:

- イベント名
- 発売日時
- `https` の販売 URL

任意項目:

- メモ

不正 URL、空のイベント名は保存しない。登録時点で発売済みの日時は新規登録できない。登録済みイベントは編集・削除できる。

発売日時は日本語の日時ピッカーで5分刻みに選択する。新規登録の初期値と発売前イベントの既存時刻が5分境界にない場合は、次の5分へ切り上げる。発売済みイベントの保存済み時刻は、メモなどを編集できるよう変更せず保持する。

### 通知

- 発売日時の 10分前、5分前、3分前、1分前にローカル通知を予約する。
- 登録時点ですでに過ぎている通知時刻は予約せず、将来分だけを予約する。
- 編集時は古い通知を取り消して再予約する。
- 削除時は関連通知を取り消す。
- 権限拒否時も登録は保存できるが、通知されないことを画面上に表示する。
- 通知にはイベント識別子を含め、通知タップ後に保存済みイベントの URL を参照する。

通知文言:

- 10分前: `発売10分前：イベント名`
- 5 分前: `まもなく発売：イベント名`
- 3 分前: `準備開始：イベント名`
- 1分前: `まもなく開始：イベント名`

### URL 起動

- `https` URL のみを受け付ける。
- 通知タップまたは一覧上の操作で、発売待機画面を開く。
- 発売待機画面で残り時間を表示し、表示中は自動ロックを抑止する。
- 発売待機画面が前面に表示されたまま発売時刻になった場合、Safariで販売 URL を1度だけ自動で開く。
- 手動ロックまたはアプリ切り替えで待機が中断された場合は自動表示を行わず、手動ボタンを表示する。
- iOS の制約により、バックグラウンドまたはロック中に Safari を自動起動しない。
- URL が不正、または対象イベントが削除済みの場合は安全に失敗し、別イベントを開かない。

### 保存と一覧

- MVP のデータは `UserDefaults` を使って端末内に保存する。
- モデルは安定した ID、イベント名、発売日時、販売 URL、メモ、作成日時、更新日時を持つ。
- 発売前のイベントを日時の早い順、発売済みイベントを日時の新しい順に表示する。
- 発売済みイベントは自動削除せず、過去イベントとして保持する。
- 保存層は将来 App Group の共有ストレージへ差し替えられる形にする。

## 非機能要件

- オフラインで登録済みイベントを確認できる。
- 秘密情報やチケットサイトの認証情報を保存しない。
- Dynamic Type と VoiceOver の基本操作を妨げない。
- 画面文言と日時入力のシステム表示を日本語で統一する。
- 入力検証、日時判定、通知候補の計算を UI から分離して単体テスト可能にする。
- 通知識別子はイベントごと・通知タイミングごとに一意にする。

## MVP 対象外

- X や共有シートからの自動取り込み
- Web ページや投稿文からの日時抽出
- 券種の自動選択
- Safari 拡張
- ログイン、購入、決済の自動化
- CAPTCHA や待機室の回避
- サーバー同期、複数端末同期
- Apple Watch 対応

## 将来拡張の設計条件

- Share Extension から URL と共有テキストを受け取れるよう、保存済みイベントとは別に下書きデータを導入できる構成にする。
- X、Safari、チケットサイト別解析、カレンダー連携をアプリ本体の保存モデルへ密結合させない。

## 受け入れ条件

- 有効なイベントを登録・編集・削除できる。
- 10分前、5分前、3分前、1分前のうち、登録時点より後の通知が予約される。
- 発売日時を日本語表示の5分刻みで選択できる。
- 通知タップから正しいイベントの発売待機画面を開ける。
- 発売待機画面の表示中は自動ロックせず、中断なく前面で待てば発売時刻にSafariが1度だけ開く。
- ロック状態やバックグラウンド状態で販売 URL を自動起動しない。
- 通知拒否、不正 URL、過去日時で利用者が次の操作を判断できる。
- アプリ再起動後も登録内容が復元される。
- 発売済みイベントが過去イベントとして残る。
- 関連単体テストが通り、実機確認結果が開発ログに記録される。
