# 編集済みシークエンス SRT v0.2.0

Premiere Proで編集中のシークエンスから手動で書き出した文字起こしJSONを、独自の整形ルールでUTF-8のSRTに変換します。UXPパネルとコマンドラインで同じ生成エンジンを使います。

## 初回セットアップ

1. 正式版の `.ccx` を開き、Creative Cloudデスクトップアプリでインストールします。ソースから開発・検証する場合はUXP Developer Toolsで `plugin/manifest.json` を追加してロードします。
2. Premiereで **ウィンドウ → エクステンション → Transcript Caption Placement** を開き、「待受中」と表示されたら待受フォルダのパスを確認します。
3. **ウィンドウ → UXPプラグイン → 編集済みシークエンス SRT** を開き、**CEP連携フォルダを選ぶ** で同じフォルダを指定します。連携フォルダは次回起動にも引き継がれます。テスト版から移行したとき、フォルダを移動したとき、アクセス権や保存した設定が失われたときは選び直してください。

既存の **Transcript Caption Placement** が複数字幕トラックの追加に対応済みであれば、そのまま使えます。古い版を更新する場合は、同梱の `cep-update/install.command` を実行し、Premiereを再起動してください。インストーラーは既存のCEP拡張機能を更新し、更新前のファイルを拡張機能フォルダの隣に退避します。

## Premiereで使う

1. Premiere起動後、直接配置する前にCEPの「待受中」を確認します。ワークスペースから復元されていなければ、その起動中に一度開きます。通常利用ではUXP Developer Toolsのロード操作は不要です。
2. 配置先のシークエンスをタイムラインで開き、そのシークエンスから手動で書き出した文字起こしJSONを **JSONを選ぶ** で読み込みます。
3. パネル上部の **ナレーションを含める** をオンまたはオフにして **生成 → このシークエンスに配置** を実行します。設定を変えた場合は再生成します。
4. 字幕トラックが1本増え、先頭の字幕が映像・音声と合っていることを確認します。同じシークエンスで逆の設定を生成し、さらに別の字幕トラックとして追加できます。

「このシークエンスに配置」を押すと、SRTをCEP待受フォルダ直下の `sequence-srt-assets` に保存してプロジェクトへ読み込みます。CEPが字幕トラックを追加してプロジェクトを保存し、UXPが配置後の字幕トラック数を照合します。配置開始前に拒否された場合は、原因を解消してパネルから再試行できます。

## コマンドラインで使う

Node.js 20以降で実行できます。追加パッケージのインストールは不要です。

```bash
node cli.js "/path/to/文字起こし.json" --out-dir "./output"
node cli.js "/path/to/文字起こし.json" --out-dir "./output" --name "シークエンス名" --by-speaker
```

出力は `.srt` と `.review.json` です。名前は、`--name`、入力のシークエンス名、入力ファイル名の順で決まります。出力先の同名ファイルは更新します。設定を変えるには、例えば `{"silenceMs":800,"correctionMs":30}` と書いたJSONを `--settings` で指定します。

| 設定 | 初期値 |
| --- | --- |
| ナレーションを含める | オン |
| 1行の最大文字数・1枚の最大行数 | 25文字・2行 |
| 1行の半角スペース上限 | 1個 |
| 句点の手前で空白結合できる文字数 | 10文字以内 |
| 空白結合後の文字数の例外 | 15文字以内 |
| 元区間をまたぐ無音での分割 | 650 ms以上 |
| 同じ元区間内で結合できる無音 | 5,000 ms以内 |
| 同一話者の軽微な時刻重複の補正幅 | 40 ms以内 |
| 短時間表示の確認目安 | 300 ms未満 |
| 最大表示時間・字幕間隔 | 初期値では無効 |

ナレーション以外は句点を削除します。句点前の本文が10文字以内、または前後を結合した本文が15文字以内なら、半角スペースでつなぎます。それ以外は改行します。10文字・15文字の判定は句読点と空白を除いて数えます。実際の表示行は半角スペースを含めて25文字以内、半角スペース1個以内です。読点も通常は半角スペースに置換し、表示行の上限に達した場合は改行します。

ナレーションは元の区間ごとに1枚にし、原文、句読点、空白、改行を保持します。ナレーションの判定には既知の専用話者ID、または「ナレーション」「ナレーター」「ナレ」「N」「NA」「Narration」「Narrator」に完全一致する話者名を使います。前後の空白と英字の大小・全角半角の差は無視します。パネル上部で「ナレーションを含める」をオフにすると、通常のSRTと話者別SRTの両方からナレーションを除きます。CLIでは `{"includeNarration":false}` を設定JSONに指定します。SRTで元の空行を表現する場合は、その行にノーブレークスペースを使います。

話者IDが変わるところは別字幕にし、IDのない発話は元区間をまたいで結合しません。表示名が同じ複数のIDはそれぞれ保持します。同じ話者でも、Premiereが前の区間末尾に `eos: true` を付けていて次の元区間に移る場合は別字幕にします。発言途中の区間境界は無音・文面・行数に応じてつなぎます。同じ元区間内では、前の語の終了から次の語の開始までが5,000 ms以内なら無音を理由に分割しません。5,000 msを超えた場合は別字幕にします。設定JSONの `sameSegmentSilenceMs` で区間内の上限を変更できます。

字幕時刻には原則として先頭語の開始、末尾語の終了を使います。1語の中に字幕境界が入る箇所では、その語の時間を文字位置に応じて按分し、確認レポートに記録します。時刻を復元できない語は、文字列と元区間・単語番号を確認レポートに残します。最大表示時間はページを分ける目安です。1行でも超過する場合はレポートに記録します。短時間の字幕は初期値で時間を引き延ばさず、レポートに記録します。

クロストークは双方の時刻を保持します。主SRTのキューが重なる場合の表示はPremiereで確認してください。個別に確認できるよう、話者ID別にも書き出せます。

## 入力JSONと時刻

文字起こしJSONの `segments[]` にある各区間の `speaker` を話者IDとして扱います。単語の `start` と `duration` はシークエンス先頭からの秒値として扱い、SRTの相対時刻に丸めます。表示タイムコードに開始オフセットがある場合は、シークエンス先頭にSRTを合わせて同期を確認してください。

## 実装ファイルとテスト

- `plugin/engine.js` — JSON解析、話者分割、整形、時刻、SRTと確認レポート
- `plugin/manifest.json`、`plugin/index.html`、`plugin/panel.js`、`plugin/panel.css` — Premiere UXPパネル
- `plugin/placement.js`、`cep-update/` — CEP連携と字幕トラックへの配置
- `cli.js` — ファイル出力と話者別出力
- `tests/` — 字幕整形、CLI出力、配置処理の自動テスト

```bash
node --test tests/*.test.js
```

公開版の自動テストは合成データを使用します。実案件の入力JSON、生成SRT、確認レポートは各案件で管理してください。既存STTの `premiere_export.py` で書き出し構造を照合し、`srt_layout.py` のUnicode文字境界の考え方を再利用しました。

2026年11月23日にPremiere Pro 25.6.6で実機確認しました。ナレーションの有無を切り替えて配置し、既存の字幕トラックがあるシークエンスに新規トラックを追加できました。Premiereを再起動した後も、インストール済みの正式版 v0.2.0 とCEPを使って字幕トラックを追加し、プロジェクトを保存できることを確認しました。自動テストは27件すべて通過しました。
