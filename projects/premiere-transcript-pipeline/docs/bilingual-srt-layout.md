# 原語・日本語訳を欠けさせないSRT表示

2026-09-26。要件定義: Astra。実装: GPT-6 Sol。Premiere Pro 2025の操作はAstraが確実な対象・操作に限定して行う。

## 採用する方式

SRTとPremiereの字幕トラックを使う。字幕静止画・動画・オーバーレイ映像は生成しない。masterの原語と日本語訳を正本とし、表示のための改行・ページ分割は書き出し側だけで行う。

SRT内で原語と訳を明示的に改行し、許容行数・行幅を超える発話は字幕を分ける。Premiere側は字幕ブロック全体の下端を安全余白内に固定し、最大行数が上方向へ伸びても収まる字幕枠を使う。下寄せだけでは長文の収容不能を解決できないため、SRT側の容量制限と必ず組み合わせる。

## 通常レイアウト

- 原語: おおむね2行、最大2行。短い発話を無理に2行へ引き伸ばさない。
- 原語は斜体。各行で装飾タグを閉じ、訳文へ装飾を持ち越さない。
- 原語と訳文の間: U+200Bを入れた間隔行を1行。完全な空行はSRTの字幕終端になるため使わない。
- 日本語訳: 最大2行。長い訳も独立に収容判定する。
- 合計: 最大5行（文字4行＋間隔1行）。日本語原語のみは対訳欄が不要なので最大4行を使い、不要な細分化を避ける。
- 語、結合文字、絵文字などの文字のまとまりを途中で壊さず、明示改行する。句読点・語境界を優先する。

## 長文と分割の規則

1. 入る発話はそのまま使い、1行ごとに細かい字幕へ分けない。
2. 入らない場合は「原語の部分＋対応する訳」を一つの字幕としてページ分割する。文字数比だけで両言語を切って意味の対応を保証したことにしない。
3. 確認済みの対応ページを利用できるようにする。ページ列の原語と訳をそれぞれ連結した内容が元の発話と一致すること、重複も欠落もないことを検査する。
4. 新たな対応境界が必要なら発話番号と原因を示して完成書き出しを止める。未確認の自動候補は完成品へ黙って採用しない。
5. 表示時刻は確認済み区間または単語時刻を使う。発話外への延長、次発話との重なり、ゼロ長・逆転を認めない。既存の対訳SRTを改行し直す場合は時刻と字幕数を変えない。
6. 文字を切り捨てたり、省略記号に置き換えたり、訳文を落としたりして収めない。読みやすさを損なう無制限なフォント縮小も使わない。

有限の字幕枠と表示時間に任意長の文章を無制限に詰め込むことはできない。収容不能なものを「完成」として通さないことを不変条件とする。

## Premiereの表示条件

SRTではフォント、実際の枠寸法、下端位置、行間を確実には固定できない。Premiereの字幕トラックスタイルとして、次の設定をSRTのレイアウト条件と一組で管理する。

- 対象シーケンス寸法・画素縦横比。
- 使用フォント・サイズ・斜体・行間。
- 字幕の下中央配置、下端の安全余白、最大5行を収容する高さと折り返し幅。
- 個別字幕の位置・サイズの上書きがある場合は、同じ条件と一致すること。

実際の字形幅はフォントに依存する。Pythonの表示幅単位による制限はデータの事前検査であり、Premiereの画面表示まで検証したことにはしない。Premiere 25で使用するスタイルが確定し、その枠に適合する上限を確認して初めて、その条件内での欠け防止が成立する。任意に大きな文字や狭い枠へ変えた状態までSRT単体で保証すると説明しない。

## 実装と運用

- 書き出し処理は原語と訳の両方を改行・検査する。完成出力は一件でも違反があれば停止する。
- ドラフトは問題と発話を明示し、レイアウト合格とは扱わない。
- 対応付け済みSRTを時刻そのままで再整形する処理を提供する。元ファイルを上書きせず、新しい版に保存する。
- 原語Transcript JSON、話者修正、翻訳本文、元素材を表示調整のために変更しない。
- 既にカット編集されたシーケンスへ素材基準SRTをそのまま差し替えない。素材確認用シーケンスと編集済みシーケンスを識別する。
- テスト素材、字幕本文、生成SRT、キャッシュはローカルに保存し、GitHubへコミットしない。

## 検証範囲

SRTデータの全文保持・最大行数・行幅・時刻の検証と、Premiereでのスタイル適合を区別して記録する。単にSRTをプロジェクトへ読み込んだだけでタイムライン反映済みとはしない。実機未確認の項目は未検証と記す。

## 初期実装の入口

`python/srt_layout.py` は、対応付け済みSRTの時刻・字幕数を変えずに明示改行する。既定幅は両言語とも44表示単位（通常の半角44文字／全角22文字相当）。これはPremiereのピクセル幅ではなく、暫定の事前検査上限である。

```sh
python3 python/srt_layout.py \
  --input /absolute/path/reviewed-bilingual.srt \
  --output /absolute/path/reviewed-bilingual-wrapped.srt
```

既存ファイルへの上書きは避け、出力は新しいファイル名にする。収容不能な字幕があれば、字幕番号と理由を返す。

確認済みページは発話の `srt_pages` に各ページの `source`、`translation`、`start`、`end` を保存する。原語・訳の全文対応と時刻を照合し、不一致は拒否する。ページ対応を編集するブラウザUIは今回の範囲外で、未実装。

日本語のみのページでは `translation` を `null` にする。既存の単語時刻をもとに対応を確認したページを指定する。ページ対応を自動で推定して確定する処理は今回実装しない。

書き出しAPIの `srt_layout_status=width-checked` はデータ上限の検査済みを表し、Premiere表示の検証済みを意味しない。`needs-review` と `srt_layout_problems` はレイアウト未解決のドラフトを示す。

## 2026-09-26の実装・検証記録

GPT-6 Solがレイアウト処理、書き出し前検査、ドラフトの画面通知を実装し、Astraが文字保持・時刻・未解決通知を中心に確認した。SRTのテスト6件、多言語機能の既存テスト16件、画面スクリプトの構文確認に合格。ローカルの確認済み83字幕は、番号・時刻・本文の非空白文字を保持して再整形できた。繰り返し再整形しても同じ結果になる。

Premiere 25での5行収容、下寄せ・枠設定の適用、稼働中サーバーの再起動・ブラウザでの新処理確認は未実施。素材基準SRTを編集中のシーケンスへ差し替えていない。

その後、実機プロパティで選択字幕のMonaco・サイズ48・下中央ゾーン・テキスト下揃えを確認した。トラックスタイルは「なし」のため、これを全字幕の統一設定が確認できた根拠にはしない。編集済み68字幕のSRTをユーザーがPremiereから書き出したので、素材基準83字幕に代えて、その編集後時刻を保持する再整形に進む。
