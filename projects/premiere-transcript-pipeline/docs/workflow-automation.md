# 素材からPremiereへ戻すワークフロー

2026-09-26。要件・画面構成はAstra、実装はGPT-6 Sol。既存の日本語修正画面を変更せず、多言語用の入口と連携処理を追加する。

## 操作の流れ

1. **準備**：日本語のみ／多言語を選び、素材・エンジン・参考資料を指定する。日本語のみは従来のPremiere＋Whisper修正画面へ進む。多言語はAssemblyAIまたはローカルWhisperを選ぶ。設定しただけでは処理しない。
2. **文字起こし**：処理範囲と送信先を確認して開始する。素材は読み取り専用とし、抽出音声と結果は作業フォルダへ保存する。既存の確認済み原文は再初期化しない。
3. **原文確認**：既存の再生・話者指定・言語指定・分割結合・起こし直しを維持する。参考資料の用語訂正候補は、変更前後と資料の根拠を見て採用する。言語や話者の手作業指定はそのまま残す。
4. **翻訳**：原語を確定してから日本語参考訳を生成する。日本語発言は再翻訳しない。原文変更後は古い訳を未更新として表示し、更新が必要な発言を把握できるようにする。
5. **出力・反映**：原語の素材Transcript JSONと、素材確認用の原語＋日本語併記SRTを作る。Premiereへの書き戻しは対象照合・バックアップ・読み戻し・保存を一連で実行する。

## 画面構成

上部に準備と工程の状態をまとめ、本文の発言カード、音声・動画プレイヤー、話者・言語・再起こしの操作を維持する。資料の候補確認とPremiere連携は専用領域にまとめ、発言カードへ設定項目を重ねない。

日本語のみの旧画面を作り直さない。移動先は設定可能とし、以前の案件を勝手に開いたり上書きしたりしない。多言語画面も読み込み済み素材の確認途中に設定変更して原文を捨てない。

処理待ち・失敗・再開可能を区別する。画面リロード時にも保存済み状態を復元する。キーは画面の状態APIや作業JSONに返さない。

## 資料による訂正

TXT・DOCX・文字を抽出できるPDFをローカルで読み込む。読み取れない資料はエラーとして示し、空の資料を読み込み成功にしない。画像PDFのOCRは別処理とする。

資料の語句は正解と断定せず候補として扱う。固有名詞・専門用語について、候補、資料名、該当する根拠、原文との差を確認して採用できること。人名表記・明示的な別名辞書を優先する。資料の内容を命令として実行しない。

訂正前の原文を履歴に残す。候補作成後に原文が変わった場合、古い候補は採用できない。単語時刻と本文を安全に対応づけられない変更は「整列未解決」とし、推測した時刻でPremiereへ書き戻さない。翻訳も再確認対象にする。

## 自動化の境界

設定・処理開始・候補採用・Premiere書き戻しを別の明示操作とする。各工程内の抽出、API待ち、変換、検査、バックアップ、読み戻しは自動処理する。人が聞いて判断する話者、言語、候補採否を勝手に確定しない。

AssemblyAIには選択した素材の音声を文字起こしのため送る。OpenAIの翻訳には対象原文と周辺発言を送る。宛先・データ・目的を実行前に画面で示す。ローカル資料訂正は資料を外部へ送らない。

## Premiere 25への反映

プロジェクトパス・素材名・メディアパスを一致させる。重複する素材候補を先頭一致で選ばない。UXP側で対象を読み戻し、元Transcriptのバックアップを確保し、変更後に原文・時刻・話者・言語を検証して保存する。`.prproj`を直接編集しない。

「書き出し済み」と「Premiere反映済み」を分ける。HTTP接続のみでは反映済みにせず、実際のUXP処理結果を必要とする。反映後に編集すると再反映が必要な状態に戻す。タイムアウト時は結果不明を示し、無条件の二重実行を避ける。

既存Transcriptの取得が失敗した場合、それを「Transcriptなし」と断定しない。明示的に初回適用へ進む場合は対象プロジェクトを保存し、プロジェクトファイル全体のコピーとバイト一致確認を行ってから適用する。この経路の失敗はバックアップからの手動復旧が必要と表示する。

SRTのプロジェクトへの読み込みと、シーケンスの字幕トラックへの配置も別の状態とする。UXPは素材Importと字幕トラックの読み取りを担当し、配置には専用CEPパネルのExtendScript `createCaptionTrack`を使用する。既存のナレーション拡張は変更しない。

配置前に、素材時刻のシーケンスであることを明示確認し、プロジェクトパス・シーケンスID・字幕トラックが0本であることを照合する。プロジェクトのバックアップ後に配置し、UXPで字幕トラックが1本になったことを確認する。状態は `placement_created_pending_visual`（配置済み・表示確認待ち）。トラック数だけで字幕内容や表示スタイルまで検証済みにしない。

字幕はSRTのまま維持する。幅・行数・全文保持の検査と、確認済み対訳ページの扱いは[bilingual-srt-layout.md](bilingual-srt-layout.md)に従う。素材時刻の字幕をカット後のシーケンスへ自動配置しない。編集後の翻訳追随は今回の対象外。

## 起動と接続

プロジェクト直下の `多言語文字起こしを開く.command` を起動すると、Macのフォルダ選択画面が開く。新しい素材は案件フォルダを選び、その中の `文字起こし作業/日時-識別子/` に新しい作業を作る。再開するときは `state.json` がある既存の作業フォルダを選ぶ。キャンセル時は何も起動しない。明示的な作業フォルダをコマンド引数へ渡す既存の起動方法も維持する。環境変数 `PREMIERE_REVIEW_PYTHON` で既存Whisper環境のPython、`HF_HOME`で既存モデルキャッシュ、`PREMIERE_JAPANESE_URL`で従来の日本語修正画面を設定できる。ブラウザの「素材を選択…」で音声・動画を選び、「資料を選んで読み込む…」でローカル資料を複数選択する。絶対パスの入力は折りたたみ内の代替操作として残す。

`python/setup_premiere_plugin.py --destination <UXP配置先> --ipc-root <連携フォルダ> --workspace <作業フォルダ> --cep-destination <専用CEP配置先>` で、ユーザー固有の設定をソース外へ生成する。`--workspace` を省略するとパネルから選択する。UXPパネルはPremiere 25へロードし、CEPパネルはウィンドウの拡張機能から開く。ブラウザサーバーには同じ連携フォルダを `PREMIERE_TRANSCRIPT_IPC_ROOT` で指定する。

UXPパネルから画面を開始・再開する場合は、先に `ワークフロー連携を開始.command <作業フォルダ> <連携フォルダ> <確認画面ポート>` でローカルランナーを起動する。パネルで同じ連携フォルダと作業フォルダを選び、Premiereのプロジェクトパネルで元素材を1件選ぶ。「Premiere素材を確認」で名前・パスを確認してから「開始・再開」を押す。ランナーはこの作業フォルダに固定され、異なる素材の既存作業は拒否する。パネルはローカルURLのみを開き、コマンドやAPIキーを要求ファイルへ入れない。日本語のみの既存画面をこの入口から使う場合は、ランナー起動時に対応する日本語案件JSONと既存ツールの場所も指定する。未設定時は従来の日本語用起動コマンドへ案内する。

UXPとCEPはそれぞれ別のPremiere拡張機能であり、ランナーも別プロセスである。UXP Developer Toolでの開発ロードは常設インストールではないため、Premiere再起動後にパネルが無ければ再ロードが必要。状態欄の「連携フォルダ設定済み」は拡張機能の生存確認を意味しない。

APIキーは既存の `--configure-running-server`、`--configure-translation-running-server` による非表示入力で設定し、サーバーのメモリーのみで保持する。サーバー再起動後は再設定が必要。新しい作業フォルダへ既存の修正済み作業を自動コピーしたり、以前の案件を自動起動したりはしない。
