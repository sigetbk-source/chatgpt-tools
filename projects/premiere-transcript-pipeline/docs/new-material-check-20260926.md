# 2026-09-26 新規素材の開始準備

## 目的と変更

新しい案件の素材・資料を選び、初回の文字起こしから既存の原語・話者・言語・日本語訳の確認画面へ進めるようにする。
正本は `chatgpt-tools/projects/premiere-transcript-pipeline`。旧 `premiere-speaker-repair` の再処理用入口とは区別する。

- 起動時に案件フォルダを選ぶと、その中に日時付きの新規作業フォルダを作成する。既存 `state.json` のある作業フォルダを指定した場合は再開する。
- ブラウザに素材と資料の選択ボタンを追加。パスを直接入力する代替操作も残す。
- 新規Whisper処理にpyannoteの話者分離を接続。Whisper用モデルキャッシュと、利用承認済み話者モデルの認証・キャッシュを分離する。
- 各実行の生結果は別の `provider/<UUID>/` に保存する。既存結果と手動修正を上書きしない。
- AssemblyAIの再開時は、送信時の素材内容と現在の素材内容を照合する。異なる場合は旧ジョブ結果を採用せず、新規作業フォルダへの切り替えを求める。
- 生結果の来歴には作業フォルダからの相対位置を残す。無音などで単語が得られない結果は確認可能な成功として扱わない。
- 長尺収録を想定し、ローカル処理の待機上限を既定7200秒に変更する。素材の長さや機種によって完走を保証するものではない。
- 素材変更時にプレイヤーの参照先を更新する。

変更対象: `python/workflow_backend.py`、`python/multilingual_review.py`、`python/native_picker.py`、`multilingual_static/`、起動コマンド、関連テスト。変更理由は新規素材の開始と既存確認画面の接続、およびモデル環境の取り違え防止。

## 確認済み

- Python全68件のテスト成功。JavaScriptと起動スクリプトの構文検査成功。
- ブラウザで35秒の架空音声の指定、参考資料1件の読み込み、開始設定保存を確認。設定保存だけではASRを開始しない。
- 素材選択のキャンセルで既存の設定を変えないことを確認。
- 実Whisperで35秒音声から単語時刻付き75語を取得。自動判定は日本語。日英混在の原語保持精度の成功とは扱わない。
- 同じ合成音声をブラウザから開始し、Whisper→pyannote→master保存→確認画面の発言カード表示まで完走。75語、2発言、確認画面上の話者は1人。pyannote生結果は2ラベル・3区間だが、元の合成台本は3人の声であり、Whisperが英語の一部を落としている。処理経路の成立と、認識・話者判定の品質は区別する。起動から表示まで約30分で、主にpyannote環境の初回読み込みに時間を要した。
- 初回処理後、同じ35秒の音声で話者分離のみを再実行すると17.92秒。修正後のコードを新しい作業フォルダに通した全体の再実行は35.2秒で `review` に到達し、送信時の素材識別情報と `provider/<UUID>/` を指す生結果の来歴を保存した。これらはキャッシュが温まった短尺音声の結果であり、長尺への外挿はしない。

## 操作

`多言語文字起こしを開く.command` → 案件フォルダ選択 → 素材選択 → 資料読込 → 言語とエンジン選択 → 設定保存 → 文字起こし開始。
AAIは開始前に外部サービス設定を行う。キーはチャットや資料に記載せず、専用の非表示入力を使う。
再開時は案件フォルダ全体ではなく、作成済みの日時付き作業フォルダを指定する。
