# GitHub 運用ルール

## 目的

GitHub 上のコード、設定、固定資産、関連 Markdown を開発の正本として保ち、人間と複数の LLM が同じ構造・仕様・検証状態を参照できるようにします。

## 共通リポジトリ方針

- 新しい分野や小規模ツールは、原則 `chatgpt-tools` に集約する。
- 再利用可能なワークフローは `skills/<name>/`、独立アプリや開発物は `projects/<name>/`、共通方針は `docs/` に置く。
- ルート `README.md` は共通入口、`AGENTS.md` は LLM 非依存の指示、`CLAUDE.md` / `GEMINI.md` は薄いアダプタとする。
- 各 skill / project の README を LLM 非依存の実装・仕様の正本とする。

## 新規リポジトリを検討する条件

次のような明確な理由がある場合だけ、新規リポジトリを検討します。

- 公開範囲またはアクセス権限を分ける必要がある
- 独立した CI/CD、デプロイ、リリース管理が必要である
- 大きな履歴、Issue、Pull Request、バージョン体系を分離する必要がある
- ライセンス、所有権、依存関係などの制約が異なる
- ユーザーが独立リポジトリを明示的に希望している

新規リポジトリが必要でも、AI 側に作成機能がない場合は、人間が GitHub UI で空リポジトリを作成し、接続確認後に AI が中身を投入します。

## 既存リポジトリの集約

- 移行前に、移行元の既定ブランチ、最新コミット、ファイル一覧、公開範囲、アーカイブ状態を確認する。
- 集約先 README に、移行元、参照ブランチ、参照コミット、コピー日、履歴移植の有無を記録する。
- 履歴を完全移植しない場合は、その事実を明記して現行ファイル一式を優先する。
- 移行元リポジトリを AI の判断だけで削除、アーカイブ、変更しない。
- ローカルだけの未push差分を、GitHub の正本と混同して取り込まない。

## 管理対象と除外対象

管理するもの:

- ソースコード、設定ファイル、スキル定義
- 実行に必要な固定資産
- 仕様、設計、運用、検証結果、変更履歴
- 用途を明記した完成サンプル

原則として管理しないもの:

- ビルド生成物、キャッシュ、一時ファイル
- 自動再生成できる中間成果物
- パスワード、トークン、証明書、署名データ、個人情報
- ユーザー固有の IDE 設定

## 変更と検証

- 作業前にルート文書と対象ディレクトリの文書を読む。
- 重要な仕様変更では、コードと関連文書を同じ変更単位で更新する。
- 実装済み、自動テスト済み、シミュレータ確認済み、実機確認済み、提案中を区別する。
- 複雑な変更は可能な範囲で独立レビューし、指摘を直して再確認する。
